ADIF → Excel ✨

把 LoTW / QRZ / Club Log / N1MM / JTDX / TQSL 导出的日志，整理成一张干净的表格。 保留原始数据、自动识别字段、附上 DXCC 实体与 QSL 平信邮资。所有时间为 UTC。

🌐 打开浏览器版 →

首次打开会下载约 10 MB 的 Python 运行时（之后浏览器会缓存，秒开）。 这是把真正的 Python 转换器搬进浏览器的一次性成本。

它是怎么做到"纯网页"的

本项目的转换逻辑是 Python（adif2xlsx.py）。 浏览器版通过 Pyodide（把 CPython 编译成 WebAssembly）把 同一份 Python 代码跑在页面里，所以：

  • 页面里跑的就是桌面版用的那份代码，不是用 JavaScript 重写的第二份实现；
  • 所有计算在本机浏览器内完成，不联网、不上传、没有服务器；
  • 生成的 Excel 由浏览器直接下载。

自动化测试会在真实的无头浏览器里跑一次转换，并核对输出与桌面版 逐单元格一致（tests/test_browser_edition.py）。

📋 输出的两张表

工作表内容
QSOs 每条通联一行。第 1 行英文列名（大写，公式和脚本用），第 2 行中文标签。 日期时间是真正的 Excel 日期时间值，不是文本。
Summary 波段 / 模式 / 呼号统计、总览、来源文件，以及逐列填充情况。 第 1 行写明数据来源和「单元格为空」的含义。

必选列（9 个，永远输出）

CALL QSO_DATE TIME_ON_UTC FREQ_MHZ BAND MODE RST_SENT RST_RCVD STATION_CALLSIGN

另有自动生成列也永远输出：SOURCE_FILE、DXCC_ENTITY、 QSL_POSTAGE_AIR。

附加列不硬编码：工具扫描 ADI 里实际出现的所有 ADIF 字段各自成列； 某字段在所有记录中都是空的，就不输出该列。所以不同来源导出的列不完全一样， 这是刻意的。

所有时间都是 UTC，不做时区换算，并在列名与表头写明。 你的日志里写的是什么时间，导出的就是什么时间。

🌍 DXCC 实体 ≠ 国家

中国 = 大陆 + 香港 + 澳门 + 台湾 + 黄岩岛；俄罗斯 = 欧洲 / 亚洲 / 加里宁格勒； 美国 = 本土 / 夏威夷 / 阿拉斯加 / 波多黎各。

DXCC 表由 ARRL 官方列表生成（2026 年 1 月版，340 个现有实体 + 62 个已删除）。 判定顺序：日志自带的 DXCC 编号 → COUNTRY → 呼号前缀。

编号是权威的：LoTW、Club Log、N1MM 都会写 DXCC。 早期版本用手写编号表，把 SP4DDS（波兰，269）判成多哥 —— 国家错、邮资也错。现在表是生成的，并有 260 个区块的自动化审计。

✉️ QSL 邮资（中国邮政 平信）

按 20 克平信计，输出到 QSL_POSTAGE_AIR。 大陆 单一数字 1.20；港澳台 航空 2.00 / 水陆路 1.50； 国际分区 1–4 档。不提供邮政服务的地区写「不通邮」。

只显示信函价格（不含明信片、不含挂号费）。资费会变，所以 Summary 表同时写明 资费生效日期与核对日期及来源 —— 一个过期的价格比没有价格更糟。

🔒 隐私

  • 浏览器版：转换在你的浏览器内完成，日志不上传，也不调用任何接口。
  • 本机服务版：只监听 127.0.0.1（其他机器连不上）， 每次运行随机 token，上传的临时文件转换后立即删除。
  • 整个项目不联网、不收集任何数据。
  • 仓库里的测试日志是合成假呼号：与真实导出的 240 个呼号 重叠数为 0，且不含机主呼号、姓名、地址、邮箱、真实网格坐标 （由 tools/audit_privacy.py 核对）。

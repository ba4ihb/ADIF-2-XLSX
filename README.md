## 直接用（推荐）：浏览器版

### 👉 <https://ba4ihb.github.io/ADIF-2-XLSX/web.html>

**打开就能用。不用下载、不用安装、不用跑任何本地程序。**

把 `.adi` / `.adif` 拖进页面 → 选好要输出的列 → 点「开始转换」→ Excel 直接下载。

| | |
|---|---|
| 🔒 **不联网上传** | 转换完全在你的浏览器内完成，日志不离开这台电脑 |
| 💻 **跨平台** | 手机、平板、Mac、Linux 都能用（桌面版只支持 Windows） |
| ⏱️ **首次约 10 MB** | 下载 Python 运行时，之后浏览器缓存，秒开 |
| 🚫 **没有服务器** | 页面不调用任何接口，没有后端 |

### 它是怎么做到的

本项目的转换逻辑是 Python（`src/adif2xlsx.py`）。浏览器版通过
[Pyodide](https://pyodide.org/)（把 CPython 编译成 WebAssembly）
**把同一份 Python 代码跑在页面里**，所以它**不是**用 JavaScript 重写的第二份实现，
而是同一个转换器换了个运行位置。

因此网页版和桌面版**不会各自漂移**——这一点由测试强制，不靠人工对齐：
`tests/test_browser_edition.py` 会核对打包进页面的源码与 `src/` **逐字节相同**，
并在真实的无头浏览器里实跑一次转换。

## 下载

不想等那 10 MB，或者网络不便？到 [**Releases**](https://github.com/ba4ihb/ADIF-2-XLSX/releases/latest)
下载。每个 ZIP **解压即用**，不需要装 Python，不需要装任何东西。

| ZIP | 界面 | 解压后双击 |
|-----|------|-----------|
| `adif2xlsx-web.zip` | 网页版（本机服务 + 浏览器界面） | `启动网页版.bat` |
| `adif2xlsx-ui.zip` | 桌面窗口版 | `adif2xlsx-ui.exe` |
| `adif2xlsx-cli.zip` | 命令行版 | 终端里调用 `adif2xlsx.exe` |
| `adif2xlsx-all.zip` | 以上全部六种构建 | 自己挑 |
| `*-onedir-v1.0.0.zip` | 文件夹版 | **启动明显更快，日常建议选它** |
| `SHA256SUMS.txt` | 校验和 | `certutil -hashfile <文件> SHA256` |

> **单文件版启动慢**：首次启动要解压到临时目录，约 8–60 秒（取决于磁盘和内存）。
> 文件夹版（`-onedir`）启动快得多。

浏览器版、本机服务版、桌面版、命令行版**共用同一份转换代码**，所以列目录、
中文标签、预设、输出格式完全一致。这一点由测试强制。

| 功能 | 浏览器版 | 本机服务版 | 桌面版 | 命令行 |
|------|:---:|:---:|:---:|:---:|

| 自动识别 ADIF 字段（不硬编码） | ✅ | ✅ | ✅ | ✅ |
| DXCC 实体 + 判定依据 | ✅ | ✅ | ✅ | ✅ |
| QSL 平信邮资 | ✅ | ✅ | ✅ | ✅ |
| 合并多个日志为一个工作簿 | ✅ | ✅ | ✅ | ✅ |
| 输出位置 | 浏览器下载 | 下载或写盘 | 写盘（默认桌面） | 写盘（默认桌面） |

## 快速开始

### 浏览器版

点 [这个链接](https://ba4ihb.github.io/ADIF-2-XLSX/web.html) 就行，无需其他步骤。

### 桌面版

1. 解压 ZIP，双击 `adif2xlsx-ui.exe`；
2. 把 ADI 文件（或整个文件夹）拖进窗口；
3. 在「要输出的列」里勾选附加列，或用「常用 / 全部 / 仅必选」快捷键；
4. 点「开始转换」，完成后可直接打开生成的 Excel。

### 命令行

```bat
:: 转换一个文件，输出到桌面
adif2xlsx.exe mylog.adi

:: 合并整个文件夹（含子目录），指定输出
adif2xlsx.exe D:\logs -r -o D:\out\all.xlsx

:: 只要必选列 + DXCC + 邮资
adif2xlsx.exe mylog.adi --columns required

:: 看看有哪些列名可用
adif2xlsx.exe --list-fields
```

### 从源码运行

```bash
git clone https://github.com/ba4ihb/ADIF-2-XLSX.git
cd ADIF-2-XLSX
pip install openpyxl

python src/adif2xlsx.py mylog.adi          # 命令行
python src/adif2xlsx.py --gui              # 桌面窗口
python src/webapp.py                       # 本机网页服务
```

## 输出的 Excel

两张工作表。

### 工作表 `QSOs`

- **第 1 行**：英文列名（大写）——这是文档化的接口，公式和脚本按它来
- **第 2 行**：中文标签——给人看
- **第 3 行起**：数据，每条通联一行
- 冻结窗格固定在 `A3`，自动筛选覆盖整个数据区
- 日期和时间是**真正的 Excel 日期/时间值**，不是文本，可以直接排序、相减

**必选列（9 个，永远输出）**：

| 列名 | 中文标签 |
|------|---------|
| `CALL` | 对方呼号 |
| `QSO_DATE` | 通联日期(UTC) |
| `TIME_ON_UTC` | 开始时间(UTC) |
| `FREQ_MHZ` | 频率(MHz) |
| `BAND` | 波段 |
| `MODE` | 模式 |
| `RST_SENT` | 发送信号报告 |
| `RST_RCVD` | 接收信号报告 |
| `STATION_CALLSIGN` | 本方呼号 |

另有三个**自动生成列**也永远输出：

| 列名 | 中文标签 | 说明 |
|------|---------|------|
| `SOURCE_FILE` | 来源文件 | 这条记录来自哪个 ADI |
| `DXCC_ENTITY` | DXCC 实体 | 判定出的实体名 |
| `QSL_POSTAGE_AIR` | QSL 邮资(RMB) | 20 克平信资费 |

还有两个自动生成列**有内容时才输出**：

| 列名 | 中文标签 | 说明 |
|------|---------|------|
| `DXCC_SOURCE` | 实体判定依据 | `ADIF_DXCC` / `ADIF_COUNTRY` / `PREFIX`，前缀有歧义时会写出其它可能 |
| `QSL_POSTAGE_DETAIL` | 邮资明细 | 例如 `航空 6.00 / 水陆路 4.00` |

**附加列不硬编码。** 工具扫描 ADI 里实际出现的**所有** ADIF 字段，各自成列；
中文标签表里有 55 个常见字段，其余字段用 ADIF 原名。

> **某字段在所有记录中都是空的，就不输出该列。** 所以不同来源导出的列不完全一样，
> 这是刻意的——Summary 表会逐列说明填充情况。

`--list-fields` 可以列出全部可用列名。

### 工作表 `Summary`

| 位置 | 内容 |
|------|------|
| **第 1 行** | 数据来源与「单元格为空」的含义（合并 A1:D1，自动换行） |
| 中部 | 总览、波段统计、模式统计、呼号 Top、来源文件清单 |
| 底部 | **逐列填充情况**——每一列有多少条有值、多少条为空 |

第 1 行放在最上面是刻意的：「这一格为什么是空的？」这个问题，是在看 `QSOs` 表时问出来的，
放在 100 多行的 Summary 底部没人找得到。

## DXCC 实体 ≠ 国家

这是本工具最容易出错、也最值得说清楚的部分。

**一个「国家」可能包含多个 DXCC 实体：**

| 国家 | 对应的 DXCC 实体 |
|------|-----------------|
| 中国 | 大陆(`B<数字>`) · 香港(`VR2`) · 澳门(`XX9`) · **台湾**(`BM`–`BQ`,`BU`–`BW`,`BX`) · 黄岩岛(`BS7`) |
| 俄罗斯 | 欧洲部分(区号 1–7) · 亚洲部分(区号 8/9/0) · 加里宁格勒(`UA2`/`RA2`) |
| 美国 | 本土 · 夏威夷(`KH6/7`) · 阿拉斯加(`KL/AL/NL`) · 波多黎各(`KP3/4`) · 关岛 · 威克岛 … |
| 法国 | 本土 · 科西嘉 · 瓜德罗普 · 马提尼克 · 留尼汪 · 新喀里多尼亚 … |

**判定优先级：**

1. 日志自带的 `DXCC` 字段 —— **权威**，直接采用
2. 日志自带的 `COUNTRY` 字段
3. 呼号前缀（最长匹配 + 特殊规则）

判定依据会写进 `DXCC_SOURCE` 列，所以每一行都能看出结论是怎么来的。

### DXCC 表由 ARRL 官方列表生成

表**不是手写的**，由 `tools/` 下的脚本从
**ARRL DXCC List（2026 年 1 月版：340 个现有实体 + 62 个已删除实体，769 条前缀）** 生成：

```bash
python tools/parse_arrl_pdf.py       <DXCC_Current.pdf> tools/data/arrl_dxcc_2026.txt
python tools/strip_glossary_notes.py <DXCC_Current.pdf> tools/data/arrl_dxcc_2026.txt
python tools/build_dxcc.py           # -> src/dxcc_tables.py
```

> `src/dxcc_tables.py` 是**生成物，不要手改**。

**为什么必须这样。** 早期版本用手写的编号表，而**编号是权威的**——
LoTW、Club Log、N1MM 都会写 `DXCC` 编号，解析器优先信任它。当时犯的错：

| 呼号 | 日志里的编号 | 手写表判成 | ARRL 列表实际是 |
|------|-------------|-----------|----------------|
| `SP4DDS` | 269 | **多哥** ❌ | 波兰 |
| `E74K` | 501 | **约旦** ❌ | 波黑 |

结果是**国家错，邮资也错**。不是漏了两个，是整个编号体系错的。

**怎么保证解析正确。** PDF 会把呼号区号、脚注号、甚至实体名的一部分粘在前缀上，
一个格子可能长这样：

| 格子里看到的 | 实际含义 |
|-------------|---------|
| `ZC442UK` | 分配 `ZC4` + 脚注 42 + 实体名里的 "UK" |
| `JD119` | `JD1` + 脚注 19 |
| `OK-OL23` | 范围 `OK-OL` + 脚注 23 |
| `9M2,4` | `9M2`, `9M4` |

**不猜哪个数字是脚注**——而是把文末的**词汇表**也读出来：每条脚注自己写明它讲的是哪个
分配（`42   (ZC4) ...`），拿这个去格子里找。修正文字全部来自文档本身，可逐条核对。

### 56 个前缀被多个实体共用

ARRL 列表里**有 56 个前缀同时属于多个实体**，而且**列表本身不说明哪个呼号区归谁**：

| 前缀 | 列表给出这些实体 |
|------|-----------------|
| `CE0` | 复活节岛 · 胡安·费尔南德斯群岛 · 圣费利克斯和圣安布罗西奥 |
| `FO` / `TX` | 法属波利尼西亚 · 克利珀顿岛 · 南方群岛 · 马克萨斯群岛 |
| `TO` | 瓜德罗普 · 马约特 · 圣巴泰勒米 · 马提尼克 · 留尼汪 · 特罗姆兰岛 · 圣马丁 |
| `3D2` | 斐济 · 罗图马岛 · 康韦礁 |
| `VK0` | 赫德岛 · 麦夸里岛 |

一次查表**只能返回一个**实体，所以工具必须选一个——**但不能悄悄选**。

**凡是前缀有歧义，`DXCC_SOURCE` 列会把其它可能写出来**：

```text
CE0Z   →  复活节岛    PREFIX (CE0 shared with Juan Fernandez Is., San Felix & San Ambrosio)
VK0AA  →  赫德岛      PREFIX (VK0 shared with Macquarie I.)
3D2AA  →  斐济        PREFIX (3D2 shared with Rotuma I., Conway Reef)
```

这样遇到稀有岛屿时，你看到的是「**这可能是复活节岛，也可能是胡安·费尔南德斯**」，
而不是一个没有任何提示的错误答案。

> **要得到确定的答案，请让日志写入 `DXCC` 编号或 `COUNTRY`**——这两者永远优先于前缀。
> LoTW、Club Log、N1MM 都会写 `DXCC`，所以真实日志很少走到前缀这条路。

子实体靠**更长前缀**仍然可以正常命中：`VK9X`→圣诞岛、`VK9L`→豪勋爵岛、
`KH7K`→库雷岛、`3B9`→罗德里格斯岛、`VK9`→澳大利亚。

### 覆盖与限制

`tests/test_dxcc.py` 里有 **48 项检查**，含 260 个区块的自动化审计与 40 余个呼号的实测清单，
覆盖中国 B 段、俄罗斯区号、美国各州、稀有岛屿，覆盖度不会悄悄退化。

**诚实说明**：ARRL 列表里少数实体的编号无法在本环境中独立核实，这些实体**只报名字**
（报告和邮资用的就是名字），编号列显示前缀而**不编造数字**。日志自带的编号始终优先。

## QSL 邮资（中国邮政 平信）

按 **20 克平信（信函）** 计算，写入 `QSL_POSTAGE_AIR` 列。

| 目的地 | 资费（RMB） |
|--------|------------|
| 中国大陆 | **1.20**（本地 0.80） |
| 香港 / 澳门 / 台湾 | 航空 **2.00** · 水陆路 **1.50** |
| 国际分区 1（含日本等，适用亚太减低资费） | 航空 5.00 · 空运水陆路 4.50 · 水陆路 3.50 |
| 国际分区 2 | 航空 5.50 · 空运水陆路 5.00 · 水陆路 4.00 |
| 国际分区 3 | 航空 6.00 · 空运水陆路 5.50 · 水陆路 4.00 |
| 国际分区 4 | 航空 7.00 · 空运水陆路 6.50 · 水陆路 4.00 |
| 不提供邮政服务 | 写「**不通邮**」并说明原因 |

- **只显示信函价格，不提供明信片价格。**
- 挂号费、回执费等附加费用**不计入**。
- 水陆路只对**实际开办该业务**的国家显示（未开办的目的地不显示该档）。
- **340 个 DXCC 实体全部有答案**：302 个给出信函价格，38 个明确写「不通邮」并说明原因——
  不会留空让人猜。

### 价格永远带出处

Summary 表写明资费标准的：

- **生效日期**：2018-12-07（中国邮政《国际函件资费表》）
- **核对日期**：2026-10
- **来源链接**

一个过期的价格比没有价格更糟，所以这两组日期必须留在文件里。

## 时间处理（请务必读一下）

- 输出**全部是 UTC**，**不做任何时区换算**
- 列名里明确写 `_UTC`（如 `TIME_ON_UTC`）
- 中文标签也写明「(UTC)」
- Summary 表再次声明

**你的日志里写的是什么时间，导出的就是什么时间。** 不猜、不改、不「帮你修正」。

## 隐私

| 措施 | 说明 |
|------|------|
| 完全本机 | 转换不联网，不调用任何外部服务 |
| 浏览器版不上传 | 数据不出浏览器，没有后端 |
| 只监听回环 | 本机服务版绑定 `127.0.0.1`，其他机器无法访问 |
| 随机令牌 | 每次运行生成新 token，地址不带 token 一律拒绝（403） |
| 路径校验 | 静态文件请求做前缀检查，防目录穿越 |
| 临时文件即删 | 上传内容在转换完成后立刻删除 |
| 仓库无真实数据 | 测试用日志是**合成假呼号** |

**关于测试数据的核对**：仓库里 `tests/fixtures/adi/` 的六份日志，是从真实导出**脱敏**而来——
呼号被替换为**等长、且落在同一 DXCC 实体**的合成呼号，个人信息字段替换为占位符。
提交前用 `tools/audit_privacy.py` 核对过：**240 个合成呼号与原始文件的 240 个呼号重叠数为 0**，
且不含机主呼号、姓名、地址、邮箱、真实网格坐标。

`samples/` 下的示例日志是**手写的虚构数据**（`Bill`、`Honolulu` 之类），不含任何真实通联。

## 命令行用法

```text
adif2xlsx.exe [输入...] [-o 输出.xlsx] [选项]
```

输入可以是**文件、多个文件、或文件夹**（文件夹会递归收集 `.adi` / `.adif`）。

| 选项 | 说明 |
|------|------|
| `-o, --output PATH` | 输出 xlsx 路径（默认：桌面 `adif_export.xlsx`） |
| `-r, --recursive` | 输入是文件夹时递归子目录 |
| `--columns NAME,NAME` | 只输出这些附加列；`required` 表示仅必选列 |
| `--list-fields` | 列出 `--columns` 接受的列名后退出 |
| `--quiet` | 只打印错误 |
| `--gui` | 打开图形界面（双击时默认） |
| `--version` | 显示版本 |

**退出码**

| 码 | 含义 |
|----|------|
| 0 | 成功 |
| 1 | 输入无法解析（文件损坏、不是 ADIF 等） |
| 2 | 参数错误，或输出路径不可写 |

## 架构说明

> **一份实现，四种界面。**

```
                      src/adif2xlsx.py
                   （解析 · 字段映射 · 写出 xlsx）
                             │
        ┌────────────┬───────┴───────┬──────────────┐
        │            │               │              │
   命令行 CLI    桌面 GUI       本机 HTTP 服务    浏览器版
   main()      gui.py          webapp.py        Pyodide
                                                 （页面内跑
                                                同一份 Python）
```

关键点：

- **网页前端不解析 ADIF。** 它把文件交给同一份 `src/adif2xlsx.py`，
  所以 DXCC 表、邮资表、列选择、Summary 的填充报告都只有一处实现。
- **浏览器版不重写逻辑。** 通过 Pyodide 在页面里跑真正的 Python 模块，
  为此核心模块新增了几个接缝，让「按路径转换」和「按内存转换」共用一份代码：
  `_decode_adif()`、`parse_adif_bytes()`、`parse_adif_text()`、
  `build_workbook()`、`workbook_bytes()`。
- **本机服务仅供本机使用。** 只绑定 `127.0.0.1`，每次运行随机 token。

> 为什么不用 JavaScript 重写一遍？因为**两份实现必然逐渐不一致**，
> 而这正是本项目要避免的。

## 已知限制

- **黑窗口**：本机服务版每次启动会弹一个黑色命令行窗口，**转换期间不要关闭**。
  这是本机服务的窗口，不是错误。
- **打包体积**：单文件 EXE 约 32 MB，解压后文件夹版约 77 MB。因为内嵌了完整的 Python 运行时。
- **单文件版启动慢**：约 8–60 秒（取决于磁盘和内存）。文件夹版明显更快。
- **少数 DXCC 编号未能独立核实**：这些实体只报名字，编号列显示前缀，不编造数字。
- **测试数据是脱敏的**：仓库里的六份日志呼号是合成的，因此它们**不能**用来验证真实日志的判定结果。
- **未在真实 Excel 中渲染验证**：开发环境没有 Excel/LibreOffice，工作簿的**内容**经过
  逐单元格核对（含打包版一致性），但**视觉效果**未经人工目视确认。
